# day03 — Подзапросы, множества и DML

Сначала запросы с подзапросами и операциями над множествами, затем изменение данных: `INSERT`, `UPDATE`, `DELETE`. После этого модуля данные в базе меняются, поэтому для следующего модуля состояние восстанавливается скриптом [`db/after-day03.sql`](../db/after-day03.sql).

| Упражнение | Что делает запрос |
| ---------- | ----------------- |
| `ex00` | пиццы с ценой 800–1000 в пиццериях, где побывала клиентка Kate, с датой визита |
| `ex01` | позиции меню, которые никогда не заказывали |
| `ex02` | то же с названиями пицц и пиццерий |
| `ex03` | пиццерии, которые чаще посещали женщины или мужчины (`EXCEPT ALL` + `UNION ALL`) |
| `ex04` | пиццерии, где заказывали только женщины или только мужчины |
| `ex05` | пиццерии, которые клиент посещал, но не делал там заказов |
| `ex06` | одинаковые пиццы по одинаковой цене в разных пиццериях (соединение таблицы с самой собой) |
| `ex07` | `INSERT` новой позиции меню |
| `ex08` | `INSERT` без жёстко заданных идентификаторов — значения берутся подзапросами |
| `ex09` | `INSERT` новых визитов |
| `ex10` | `INSERT` заказов на новую пиццу, идентификаторы берутся подзапросами |
| `ex11` | `UPDATE`: скидка 10 % на пиццу |
| `ex12` | массовый `INSERT ... SELECT`: заказ для каждого клиента |
| `ex13` | `DELETE` созданных заказов и позиции меню |
