# day08 — Транзакции и уровни изоляции

Практическое знакомство с ACID: воспроизведение классических аномалий конкурентного доступа и способов их избежать. База: [`db/after-day04.sql`](../db/after-day04.sql).

Каждое упражнение — сценарий для **двух параллельных сеансов** `psql`. В `dayNN_exNN.sql` команды помечены комментариями `-- session #1` и `-- session #2`; их нужно выполнять по очереди в двух терминалах. В папке упражнения лежат скриншоты вывода `psql` для каждого сеанса (`session_1.png`, `session_2.png`).

| Упражнение | Сценарий |
| ---------- | -------- |
| `ex00` | простая транзакция: изменения не видны другому сеансу до `COMMIT` |
| `ex01` | аномалия потерянного обновления (*Lost Update*) на стандартном уровне изоляции |
| `ex02` | то же на `REPEATABLE READ`: второй сеанс получает ошибку сериализации |
| `ex03` | аномалия неповторяющегося чтения (*Non-Repeatable Read*) |
| `ex04` | то же на `SERIALIZABLE` |
| `ex05` | аномалия фантомного чтения (*Phantom Read*) |
| `ex06` | то же на `REPEATABLE READ` |
| `ex07` | взаимная блокировка (*Deadlock*): сеанс получает ошибку `deadlock detected` |
